## Current diagnostic implementation

Each new classification receives a generated `x-classification-id` response header. Safe structured logs bind that ID to image SHA-256, decoded size and submitted MIME (when inline bytes are available), prompt SHA-256, requested model identifier or alias, provider-reported model version when provided, attempt number, upstream HTTP status, elapsed milliseconds, processing stage, and normalized outcome code. The production primary is the rolling alias `gemini-flash-lite-latest`, not a permanently pinned model. Add Item detects JPEG/PNG MIME from the submitted bytes instead of relying on the server's JPEG default. A provider HTTP 4xx other than 429 is identified as an upstream error instead of a generic internal failure; quota 429 still falls back once. JSON absence, invalid JSON, invalid schema, guardrail refusal, network, timeout and upstream 5xx are separately attributable. No image bytes, URLs, raw provider output, image-derived colour/hue values, user IDs, API keys, or exception messages/stacks are logged.

The request uses the current `GEMINI_PROMPT` hash, existing `gemini-flash-lite-latest` primary and `gemini-2.5-flash` quota-only fallback. The primary alias is not pinned; a reproducible evaluation requires the provider-reported model version. These diagnostics are **prospective**, not reconstructed historical traces. Offline mocked HTTP coverage is in `__tests__/gu17Diagnostics.test.ts`; these tests exercise both a valid wrapper (with unsupported aso-oke fabric omitted) and failure/guardrail paths without a provider call. The protected synthetic GU suite and benchmark results remain untouched.
