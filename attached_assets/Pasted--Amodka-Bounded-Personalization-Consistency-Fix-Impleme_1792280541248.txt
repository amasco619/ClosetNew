# Amodka — Bounded Personalization Consistency Fix

Implement the five targeted fixes from the completed read-only onboarding personalization audit. This is a narrow correctness and testability pass, not a recommendation-engine redesign.

## Required changes

1. **Account-safe profile hydration**
   - Prevent profile values from one signed-in account being reused as fallback values for a different account.
   - Preserve intentional guest-to-account profile migration and existing local guest behaviour.
   - Correctly distinguish an unset remote field from a value intentionally supplied for the current account.
   - Add regression tests for switching between accounts with different and null profile fields.

2. **Face-shape migration**
   - Ensure guest-to-account migration copies the existing top-level face-shape value into the established `constraints._profile.faceShape` representation.
   - Preserve other constraints and profile values.
   - Avoid a database/schema migration unless demonstrably unavoidable.

3. **Primary style-goal skip**
   - Make “Skip — use defaults” consistent with onboarding completion and normal startup routing.
   - Use the existing Classic blueprint fallback or save the equivalent documented default; choose the smallest coherent solution.
   - Test skipping, app restart, and subsequent onboarding completion.

4. **Face-shape rotation hash**
   - Include face shape in the existing pool hash if it is part of the personalization inputs.
   - Add a focused offline test proving that changing only face shape invalidates the rotation state when appropriate.
   - Preserve deterministic rotation behaviour for unchanged inputs.

5. **Eye-colour and skin-tone tests**
   - Add isolated scorer tests that demonstrate the implemented effect of changing eye colour and skin tone under controlled wardrobe metadata.
   - Test both a supported match and a non-match/no-effect case.
   - Do not change score weights or expand the supported palettes in this pass.
   - Correct stale scoring comments to match the actual implementation.
