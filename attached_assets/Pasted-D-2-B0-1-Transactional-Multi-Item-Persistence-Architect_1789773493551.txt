D.2 B0.1 — Transactional Multi-Item Persistence Architecture

This is a READ-ONLY architecture task. Do not implement anything.

Using the approved Phase B specification, design the exact transactional/idempotency architecture required for authenticated multi-item wardrobe persistence.

Goal

Define how Amodka can guarantee:

success

all WardrobeItems + one GarmentGroup + all memberships

OR:

failure

no new WardrobeItems + no group + no memberships

and safely replay a request when the client cannot determine whether the original database transaction committed.

Investigate
Existing wardrobe_items primary/unique constraints.
Existing garment_groups schema and create_garment_group(...).
Existing account-deletion semantics.
Existing RLS/ACL model.
Whether the approved Phase A RPC can safely participate in the required transaction.
Whether a new orchestration RPC can call/reuse existing Phase A logic without violating security or transaction semantics.
The minimum additional database structure required for idempotency.
