AMODKA — UK SPELLING SWEEP (display strings only)

RULES
Commit in two phases (A: strings; B: display-label map and tests); run 
npm test, typecheck, lint and the golden set after each. DO NOT TOUCH: 
Recommendation Engine v3.7 source, the golden set, benchmark fixtures 
and the 53 frozen files, database schema/RLS, billing, auth. List 
deviations; never claim unverified things as verified.

TARGET
Every user-facing string uses UK spelling: -ise / -isation / -yse 
(personalise, digitisation, analyse), -our (colour, favourite, 
behaviour), -re (centre, fibre, metre), jewellery, catalogue, grey, 
licence (noun) / license (verb), and similar. Cover app screens, 
components, toasts, dialogs, accessibility labels, quiz and onboarding 
copy, paywall copy, and server messages that surface in the UI.

NEVER CHANGE
Identifiers, object keys, enum and stored values (for example 
colorFamily: 'gray', category/subtype keys such as 'jewelry'), API 
payload fields, database values, classifier JSON schema values, route 
names, analytics event names, env vars, file names, package names, 
third-party names, and user-generated content.

STEPS
1. Audit: list every user-facing US spelling with file and line, 
   grouped by screen.
2. Where a stored value is displayed (such as 'gray' or 'jewelry'), 
   add or extend a single presentation-layer label map so the UI shows 
   "Grey" / "Jewellery" while the stored value is unchanged. Test the 
   map.
3. Engine-generated user-facing text (outfit explanations and similar): 
   do NOT edit engine files. Report the strings. If a single render 
   choke-point exists, add a conservative, case-preserving, 
   word-boundary, unit-tested US-to-UK normaliser there; otherwise 
   report only. Confirm the golden set and benchmark checks are 
   unchanged.
4. Garment vocabulary: DO NOT CHANGE any category, subtype or garment-
   name labels (for example "sneakers"); the primary market is Nigeria 
   and the current terms stay. Report only: any label that differs 
   between UK and US usage (pants/trousers, sweater/jumper, vest/
   waistcoat, and similar), with file and line, so it can be reviewed.
5. Optional: add a script scripts/check-uk-spelling.mjs scanning string 
   literals under app/ and components/ against a denylist with an 
   allowlist file for identifiers; not part of npm test.

DELIVERABLE
Short report: the audit list, files changed, the label map, how engine 
text was handled, the vocabulary report, "Deviations", and what you 
did not verify on a device.

MECHANICAL SEARCH REQUIREMENT
The previous language audit missed known strings (for example 
"Personalized wardrobe blueprint" in premium copy; also "Eye Color" and 
"Pick the dominant color family"). Run a mechanical search, not a visual 
review, over app/, components/ and any user-visible server messages, 
using a denylist that includes at least: color, gray, personaliz, 
organiz, customiz, optimiz, analyz, digitiz, favorit, jewelry, catalog, 
center, fiber, neighbor, behavior, and "ize"/"ization" word endings. 
Report the match count per term and the disposition of every match 
(changed, identifier or stored value left alone, or excluded and why). 
Include premium/paywall copy and RevenueCat-facing display strings 
that live in code.
