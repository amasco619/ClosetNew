AMODKA — BULK UPLOAD: "Loading bitmap failed" (FIX + KEEP DIAGNOSTICS)

EVIDENCE
Device diagnostic (signed-in, Android, current bundle verified by 
build stamp): every bulk card fails at stage image-resize with:
 "Call to function 'Context.renderAsync' has been rejected. -> Caused by: 
  Could not load the image -> java.lang.Exception: Loading bitmap failed"
 uriScheme=file, ext=jpeg, queue=true, elapsed 12-17 ms.
- 12-17 ms is too fast to be a decode; the file likely could not be 
  opened at all.
- The same two photos work in single Add Item (same manipulateAsync call).
- The serial queue passed its tests; the error is native.
The difference between single and bulk: bulk passes file URIs through 
expo-router route params to /bulk-review, and they are used later.

PHASE 2 — THE FIX (do it now; it addresses both likely causes)
1. Stage immediately: in the multi-select picker callback, BEFORE

2. Stop sending file URIs through route params. Store the staged URI list

3. Cleanup: delete a photo's staged file after it is saved successfully,

5. Keep all existing tests passing; update the ones tied to the route
