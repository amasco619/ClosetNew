TASK: Track D.2 — Co-ord / Multi-Item Representation Contract

Read `AMODKA-PROJECT-STATUS.md` first.

OBJECTIVE

Design the canonical representation contract Amodka should use for multi-item wardrobe images and coordinated sets/co-ords.

THIS IS A DESIGN/SPECIFICATION TASK ONLY.

Do NOT modify production code, database schema, migrations, benchmark fixtures, Recommendation Engine v3.7, scoring/ranking, outfit generation, affinity, weather, classifier implementation, or UI.

Do NOT implement the proposed design.

CONTEXT

Track D.1 confirmed that GU-29 remains a genuine representation limitation:

- Reference: Ankara blazer-and-wide-leg-trouser coordinated set
- Current classifier correctly detects that multiple clothing items are present
- Current classifier contract represents one category/subtype
- Current response therefore rejects the image with `content_guardrail`
- Track D taxonomy changes do not solve this problem

The desired product principle is:

A co-ord should represent a relationship between independently wearable wardrobe pieces, rather than becoming one indivisible garment.

The design must preserve the ability for Amodka to:
- understand that pieces belong to a coordinated set
- store/style each piece independently
- preserve their original set relationship
- distinguish a genuine coordinated set from an arbitrary multi-item photograph
- avoid incorrectly treating layered clothing as a coordinated set

5. CONFIDENCE / UNCERTAINTY
