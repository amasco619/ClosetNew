1. REPLACE STRING-PARSING WITH TYPED ERRORS
Today errors are thrown as strings like "[signUpWithEmail] <msg>" and 
the screen strips prefixes and displays whatever is left. Replace this:
- Create a small AuthError class (code + optional retryAfter) with codes:
  invalid_credentials | account_exists | email_not_confirmed | 
  weak_password | invalid_email | rate_limited | network | 
  oauth_cancelled | unknown
- Map server responses and Supabase errors to these codes inside 
  lib/emailSignIn.ts, lib/emailSignUp.ts and lib/auth.ts. Wrap every 
  `await res.json()` in try/catch so a non-JSON body (HTML error page, 
  proxy failure, timeout) becomes `network`, not an unhandled parse error.
- The UI must NEVER display a raw server/Supabase message or a 
  "[functionName]" prefix. Display only copy from the catalogue in step 3.
- User-cancelled Google/Apple sign-in (oauth_cancelled) shows NO error.
- Keep the existing test override pattern (_testOverrides) working and 
  keep all existing auth tests passing. Add tests for each code mapping.

(If this conflicts with an existing deliberate decision in the live code,

- POST /api/auth/sign-up currently returns { success: true,

- Sign-in must stay non-enumerating: wrong password and unknown email

3. COPY CATALOGUE (calm, warm, no exclamation marks, no blame, no jargon)
Each entry = short title + one supporting line + optional action.
- invalid_credentials — "Those details don't match" / "Check your email 
  and password, or reset your password." Action: "Reset password"
- account_exists — "You already have an account" / "This email is 
  already part of Amodka." Action: "Sign in instead" (switches to 
  sign-in mode and pre-fills the email)
- email_not_confirmed — "Please confirm your email" / "We've sent a link 
  to your inbox." Action: "Resend link" (only if a resend path already 
  exists; otherwise omit the action)
- weak_password — "Let's strengthen that password" / state the 
  requirement that failed
- invalid_email — "That email doesn't look right" / "Please check for 
  typos."
- rate_limited — "Let's take a short pause" / "Too many attempts. Please 
  try again in a few minutes."
- network — "We couldn't reach Amodka" / "Check your connection and try 
  again." Action: "Try again"
- unknown — "Something went wrong" / "Please try again in a moment."
Polish the wording if you see a better fit, but keep the tone.
