AMODKA — GUEST-TO-ACCOUNT MIGRATION (keep what the guest added)

Symptom: a guest added 3 garments, was prompted to create an account, 
created one, and the garments disappeared. Expected: they carry into 
the new account's wardrobe automatically.

DO NOT TOUCH: Recommendation Engine v3.7, database schema/RLS (no 
migrations), billing, quota semantics, AI consent logic. Migration makes 
NO third-party AI calls and never shows the consent sheet. Keep npm 
test, typecheck, lint and the golden set green.

STEP 0 — AUDIT (report)
How guest items are stored (keys, ids, image URIs); what happens on 
sign-up and on sign-in; what clears the guest items and why (likely 
the account-switch cleanup that prevents cross-account leakage); the 
existing insert path (insert_wardrobe_items batch RPC, uploads to 
wardrobe-images with signed URLs); and any existing pending / local-
only sync mechanism.

BEHAVIOUR
1. After a successful sign-up OR sign-in from a guest session that has 
   local items: upload the photos to the user's folder in 
   wardrobe-images and insert the rows through the existing batch RPC 
   (same fields), using a stable per-item migration id so retries never 
   duplicate. Mark items synced only after confirmation.
2. Respect the free cap (30): migrate in created order up to the 
   remaining allowance; keep any remainder local and pending (never 
   delete), and tell the user calmly.
3. Never clear a guest item until its upload is confirmed. On failure 
   or offline, keep it pending and retry on the next app open or 
   foreground using the existing mechanism; show a quiet "Syncing your 
   wardrobe" state and never block the UI.
4. Keep the cross-account protection: only items created in the guest 
   session that just authenticated are migrated; items belonging to a 
   previous account are never copied into another; already-migrated 
   items are never copied twice.
5. Signing in to an EXISTING account from guest mode merges, never 
   overwrites, within the cap, deduped by migration id.
6. No background removal, no classification and no quota use on 
   migrated items.
7. UI: after authentication the wardrobe shows the migrated items 
   without a restart, plus a one-time calm note, "Your N pieces are now 
   in your account."

TESTS
Pure-function tests for the migration plan (cap math, ordering, 
idempotency keys, partial failure, retry), a stub-based proof that no 
AI or background-removal function is called, and the cross-account 
guard.

DELIVERABLE
Report: audit (what cleared the items and why), implementation summary, 
tests, "Deviations", and what you did not verify on a device.
