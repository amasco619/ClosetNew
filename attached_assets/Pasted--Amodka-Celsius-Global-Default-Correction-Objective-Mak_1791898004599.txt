# Amodka — Celsius Global Default Correction

## Objective
Make Celsius (°C) the global default temperature unit across Amodka, with Fahrenheit (°F) available only as an explicit user preference.

## Existing implementation
Inspect the current temperature-unit preference, weather normalization, display formatting, cached weather data, and relevant tests before changing code. Reuse the existing architecture and preference mechanism wherever possible.

## Exact changes
1. Make Celsius the default when no explicit temperature-unit preference exists, regardless of country or location.
2. Preserve an explicitly selected Fahrenheit preference; do not silently overwrite saved user choices.
3. Ensure weather values are normalized and displayed consistently. Do not convert an already-Celsius value as if it were Fahrenheit, or vice versa.
4. Review cached weather data and fallback paths for unit mismatches. Correct only what is necessary to maintain consistent units.
5. Update or add focused regression tests covering:
   - No saved preference → Celsius.
   - Explicit Celsius preference → Celsius.
   - Explicit Fahrenheit preference → Fahrenheit.
   - UK location with no saved preference → Celsius.
   - Weather display and cached/fallback values do not undergo accidental double conversion.
6. If a relevant preference or formatting path already behaves correctly, leave it unchanged.

## Protected areas
- Do not modify Recommendation Engine v3.7 scoring, ranking, candidate generation, affinity, rotation, or weather decision logic.
- Do not redesign weather handling or the settings UI.
- Do not add dependencies, database migrations, new provider integrations, or unrelated refactors.
- Do not change the existing weather thresholds or interpretation of temperature.
- Do not bundle Concierge, packing, notifications, payments, or other launch work into this task.

## Validation
Run the smallest relevant test set first, followed by the project’s required typecheck and any directly relevant checks. Inspect the final diff to confirm the change is limited to temperature-unit defaults, formatting/conversion where required, and focused tests.

## Stop condition
Stop when the default and explicit-preference behavior is correct, focused tests pass, and the diff confirms Recommendation Engine v3.7 remains unchanged. If the existing architecture cannot satisfy the requirements without a broader change, stop and report the blocker rather than expanding scope.

## Final report
Provide:
- Files changed and why.
- The previous and corrected default behavior.
- How explicit Fahrenheit preference is preserved.
- Tests and validation results.
- Confirmation that v3.7 and weather decision logic were not changed.
- Any unresolved blocker, or “None.”
