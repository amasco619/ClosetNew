PHASE 5C.3 — NIGERIA/AFRICA FASHION INTELLIGENCE
Track A — Discovery, Capability Audit & Gold-Standard Benchmark v1
Objective

AuraCloset/Amodka's initial commercial market will be Nigeria and wider Africa, followed subsequently by the UK and global markets.

The objective of this phase is not to modify the Recommendation Engine yet.

The objective is to establish, with evidence:

Can the existing Amodka recommendation pipeline correctly understand, classify, generate, constrain, score and rank Nigerian/African fashion?

We must determine where the existing system succeeds and where it fails before changing production recommendation behaviour.

CRITICAL RULE — NO RECOMMENDATION ENGINE CHANGES

Recommendation Engine v3.7 is frozen.

Do NOT:

change scoring weights;
change ranking logic;
change candidate-generation logic;
change constraints;
add African-specific score bonuses;
add Ankara-specific penalties/bonuses;
change body-proportion scoring;
change material scoring;
change pattern-safety scoring;
change weather scoring;
change occasion scoring;
modify the existing golden regression set;
modify production recommendation behaviour.

Do NOT create a "Nigeria mode" that changes recommendation behaviour.

Do NOT hard-code:

Ankara = traditional
African = traditional
African print = unsuitable for modern outfits

or any equivalent assumption.

The purpose is to discover whether such assumptions exist and whether they are actually harmful.

PART 6 — CULTURAL VS FASHION CONTEXT

This is a critical product requirement.

The system must distinguish:

cultural relevance

from:

fashion compatibility.

For example:

Ankara does not automatically mean:

"traditional occasion only."

A modern Ankara blazer may be appropriate for:

smart casual;
business creative;
dinner;
contemporary event.

Likewise, an agbada may be completely inappropriate for ordinary office wear even though the garment itself is high quality.

Evaluate whether the current engine has sufficient contextual information to make this distinction.

PART 9 — ADVERSARIAL TESTS

Create adversarial tests specifically targeting likely African-fashion failure modes.

Examples:

Pattern overload

Ankara + Ankara + heavily patterned accessory.

Pattern suppression

Ankara + plain neutral ground.

The system should not automatically punish the second simply because it contains a print.

Cultural mismatch

Beautiful agbada selected for ordinary office use.

Occasion mismatch

Ankara casual outfit selected for a black-tie event.

Over-formalisation

Traditional garments ranked above more appropriate contemporary outfits simply because they score highly on "formality."

Western-default bias

Plain Western outfit consistently outranking culturally appropriate African outfit without a legitimate styling reason.

Material bias

Luxury material/completeness score overpowering cultural/occasion suitability.

Weather mismatch

Heavy traditional outfit recommended during extreme heat when a lighter appropriate alternative exists.

PART 12 — IDENTIFY SYSTEMATIC BIASES

Specifically investigate:

Western-fashion bias

Does the engine systematically prefer Western clothing?

Pattern bias

Does it penalise African prints unnecessarily?

Formality bias

Does it confuse "traditional" with "formal"?

Material bias

Does expensive/luxurious material overwhelm contextual appropriateness?

Completeness bias

Does completeness overwhelm cultural/occasion suitability?

Silhouette bias

Does the current silhouette logic behave differently for African garments?

Cultural-context blindness

Does the engine lack enough context to understand why a garment is appropriate?

Every finding must include evidence.

Do not label something a bias merely because one scenario produced an undesirable result.

PART 13 — DO NOT FIX YET

At the end classify every problem into:

A — No change required

The existing engine already handles it.

B — Taxonomy/data representation problem

The engine cannot reason about information it never receives.

C — Candidate-generation problem

Valid African combinations are never generated.

D — Constraint problem

Valid combinations are eliminated.

E — Ranking problem

Good combinations are generated but ranked incorrectly.

F — Classification problem

Garments are being incorrectly classified.

G — External AI limitation

The problem originates in image/garment analysis rather than recommendation logic.

This classification is extremely important.
