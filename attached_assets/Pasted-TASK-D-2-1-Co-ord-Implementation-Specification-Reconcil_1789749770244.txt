APPROVED DESIGN PRINCIPLES

1. Existing `WardrobeItem` remains the canonical identity of each independently wearable garment.
2. Do not collapse a coordinated set into one wardrobe item.
3. Use an explicit relationship/group entity rather than a mandatory `setId` on `wardrobe_items`.
4. Initial relationship types:
   - coordinated_set
   - multi_item
   - layered
5. Garments may participate in multiple distinct relationship contexts.
6. Duplicate garment/group membership must be prevented.
7. AI-inferred relationships are distinct from user-confirmed relationships.
8. Do not introduce an automatic relationship-confidence threshold yet.
9. Uncertain multi-item relationships remain `multi_item` rather than being promoted to `coordinated_set`.
10. Group-level shared attributes are evidence/provenance, not new Recommendation Engine inputs.
11. Existing single-garment records must remain valid without migration where possible.
12. Recommendation Engine v3.7 MUST remain completely unchanged.
13. Existing scoring, ranking, affinity, fingerprints, wear history, rotation and weather logic MUST remain unchanged.
14. Preserve durable source-image provenance, reusing an existing mechanism if the codebase already provides one.
15. Do not create redundant source-image infrastructure if an adequate existing mechanism exists.
16. No UI implementation in Phase A.
17. No Gemini/classifier implementation in Phase A.
18. No benchmark fixture changes.
