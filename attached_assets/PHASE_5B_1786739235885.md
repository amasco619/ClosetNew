TRACK C — PRIVATE WARDROBE STORAGE



This is a production security requirement.



The wardrobe bucket must not remain publicly readable.



Supabase states that public buckets bypass access control for retrieval: anyone possessing the asset URL can access the file. Private buckets instead require RLS-authorised downloads or signed URLs.



Required architecture



Move the wardrobe-image bucket to:



PRIVATE



Then implement appropriate access control.



The preferred architecture is:



Authenticated user

&#x20;      ↓

Supabase Auth

&#x20;      ↓

RLS

&#x20;      ↓

Private wardrobe bucket

&#x20;      ↓

Short-lived signed URL

&#x20;      ↓

Mobile app



Supabase supports signed URLs for private assets.

C3 — SIGNED URL SECURITY



Use appropriately short-lived signed URLs for private image display.



Do not expose permanent public URLs.



Do not log signed URLs containing access tokens.



Supabase notes that signed URLs are the normal mechanism for serving private assets, but cache behaviour and token expiry are separate concerns.



Therefore test:
