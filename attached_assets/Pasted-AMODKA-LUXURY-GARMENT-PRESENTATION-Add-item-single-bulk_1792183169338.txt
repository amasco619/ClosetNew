PROBLEM
Garments appear on BLACK before saving (single add preview and bulk-review 
cards) and on garment-coloured tiles in the wardrobe. Everything should 
sit on one consistent neutral "studio" surface.

LIKELY ROOT CAUSE (VERIFY BEFORE CHANGING)
In the add-item flow, Photoroom's transparent PNG is converted to a JPEG 
via ImageManipulator (SaveFormat.JPEG) and that file URI becomes the 
preview. JPEG has no alpha, so transparency is flattened to black. 
bulk-review.tsx has similar JPEG re-encodes. Wardrobe thumbnails fill 
their container with a colour-family swatch.

STEP 1 — PIPELINE (fix at the source)
- The transparent PNG is the single source of truth for display and 
  storage. Never convert it to JPEG for preview or storage, in either flow.
- Preview: write the PNG to the cache directory (expo-file-system, 
  base64 -> .png file) and use that file:// URI. Keep large base64 
  strings OUT of React/wardrobe state, as the existing code already 
  requires.
- Keep the .png extension when copying the guest local copy, and make 
  sure the upload path uploads the PNG.
- Cutout detection for display: use a persisted flag if one exists; 
  otherwise detect by PNG format/extension. Avoid a database migration 
  unless there is no other reliable way, and tell me if you need one.
- Gemini input: do NOT send black-flattened images. Send the cutout 
  with its true mime type and have the server flatten it onto the same 
  neutral stone surface (about #E9E4DC) before forwarding to Gemini 
  (use sharp if installed; check the express.json body limit). Test a 
  black, a white and a bright garment; if colour labels get worse, 
  revert only this sub-step and tell me.
- If not already done: after Photoroom returns, trim transparent padding 
  to the subject's bounding box and add a small even margin so garments 
  have consistent scale. Do not touch quota counting, rate limits or 
  cache-key logic.

STEP 2 — GarmentTile (shared component)
Variants: "list", "grid", "preview" (large, single-add screen), "card" 
(bulk review).
- Surface: warm neutral gradient (expo-linear-gradient) about #F3F0EB -> 
  #E9E4DC, tokens added to constants/colors.ts. Light garment families 
  (white, cream, beige) get a slightly deeper stone (about #E4DED5) for 
  contrast. NEVER derive the surface from the garment's own colour.
- Garment: expo-image, contentFit="contain", centred, filling roughly 
  75-80% of the tile, consistent visual scale across dresses, bags, shoes.
- Grounding: soft, low-opacity warm floor shadow under the garment 
  (react-native-svg RadialGradient only if already a dependency; 
  otherwise a plain low-opacity ellipse). No new heavy dependencies.
- Frame: 1px hairline border (existing glass/border tokens), radius 
  matching neighbouring cards.
- No cutout (guest, limit reached, removal failed): same tile and frame 
  with the original photo at contentFit="cover". Never black.
- Loading to ready: while background removal runs, show the original 
  photo in the same frame; when the cutout arrives, crossfade 
  (expo-image transition about 300ms) to the cutout on the studio 
  surface. Respect reduce-motion.
- Memoise tiles; use recyclingKey/downsized sources in the bulk list so 
  many large PNGs don't exhaust memory.
