1. GUEST DATA RULE (product decision; supersedes merge behaviour)
- Guest signs in to an EXISTING account: discard ALL guest data (items, 
  local photo files, migration claim/journal for that sign-in, guest 
  onboarding and personalisation answers). The existing account's 
  wardrobe and profile are authoritative. Guest answers must NEVER 
  overwrite or merge into an existing account's profile. No migration 
  is attempted.
- Guest creates a NEW account (no wardrobe items AND no saved 
  onboarding/personalisation): absorb the guest data (wardrobe via 
  the existing migration; guest answers as the existing profile 
  migration does).
- Decide from the authenticated account's server-side state at first 
  sign-in, not from which button was tapped, so Google/Apple 
  sign-in and sign-up behave correctly. Evaluate ONCE, before any 
  guest data is written to the account, and persist the decision in 
  the claim; never re-evaluate after migration writes begin (the 
  migrated profile would make the account look non-empty).
- If the state cannot be read (offline or error), neither discard nor 
  absorb: keep guest data pending and decide when it can be read. 
  Never discard on an ambiguous read.
- Discard only after the decision is confirmed, using the existing 
  file cleanup.
- Sign-in screen: when guest items exist on the device, show a quiet 
  inline notice above the form: "Signing in to an existing account 
  won't keep the N pieces you added as a guest." In sign-up mode: 
  "Your N pieces will be added to your new account." N comes from 
  local data. No extra confirmation tap.
- Verify and report what the existing guest-profile migration does 
  today when signing in to an existing account (overwrite risk), and 
  fix it to match this rule.
- Tests: decision table (existing with items / existing empty but 
  onboarded / truly new / read failure), no overwrite of an existing 
  profile, discard cleans files, no claim for existing accounts, 
  ambiguity keeps data pending, decision persists once.
