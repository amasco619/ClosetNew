P0.2 — Canonical Wardrobe → Styling Intelligence Contract

Objective
Implement only the deterministic boundary that converts Amodka's canonical, user-confirmed wardrobe semantics into the semantic contract consumed by Styling Intelligence.

This is an architecture/integration foundation task, NOT a recommendation-engine improvement.

Existing implementation
- P0.1 is complete and production-validated.
- Canonical wardrobe semantics are now durably persisted.
- User corrections are authoritative, including explicit clearing of values.
- Saved-item edits persist to Supabase.
- Unknown values remain unknown.
- Existing African taxonomy remains unchanged.
- Phase A garment groups are production-approved.
- Recommendation Engine v3.7 is FROZEN.
- The African Fashion Capability Audit and Stylist Independence Audit are the source of truth for this work.
- Do not perform another whole-repository audit.

Goal
Create a small, deterministic Styling Intelligence semantic adapter/contract between canonical WardrobeItem data and the existing recommendation machinery.

The adapter must represent only information already supported by the canonical wardrobe model and existing Phase A relationships.

Required semantic boundaries

1. GARMENT ATTRIBUTES
Preserve canonical values such as:
- category
- subtype
- primary colour
- accent colour
- pattern
- pattern scale
- material/fabric
- fit
- perceived/visual weight
- neckline
- sleeve length
- rise
- warmth
- formality
- season
- occasion suitability
- metal tone
- perceptual colour

Do not invent missing values.

2. RELATIONSHIPS
Consume existing Phase A garment-group information where available:
- coordinated_set
- multi_item
- layered

Represent group membership and relationship metadata explicitly.

Do not rebuild garment groups.
Do not create a second relationship system.

3. USER AUTHORITY
The adapter must consume the canonical persisted value, not re-run AI interpretation.

Authority order must remain:
user-confirmed canonical value
> explicitly stored canonical value
> deterministic derived value
> AI suggestion
> subtype/default inference

Do not allow lower-authority inference to overwrite or silently replace a higher-authority canonical value.

An explicit user-cleared value must remain unknown.

4. DERIVED STYLING SIGNALS
Where required by the existing styling contract, derive deterministic signals from canonical data.

Derived signals must be:
- deterministic
- explainable
- reproducible
- based only on canonical data
- testable

Do not introduce an LLM or another general-purpose recommendation model.

Do not make hidden Gemini calls.

Do not create a second recommendation engine.

5. AFRICAN FASHION
The adapter must preserve existing African garment semantics rather than collapsing them into generic Western equivalents.

Examples already supported include:
- buba
- iro
- wrapper
- iro-and-buba
- boubou
- aso-ebi
- gele
- headwrap
- head-scarf
- structured-headpiece
- wax-print
- lace/chiffon
- kaftan

Do not expand the taxonomy during this task.

Do not infer:
- cultural identity
- authenticity
- aso-ebi participation
- ceremony role
- required headwear
- traditional-event requirements
- African-only vs African+Western intent

Those belong to later context/intent work.

6. UNKNOWN MUST STAY UNKNOWN
Do not substitute generic values merely because Styling Intelligence expects a field.

Examples:
- unknown formality must not become casual
- unknown season must not become all-season
- unknown material must not become a subtype-derived fabric
- unknown cultural context must not become traditional
- missing accent colour must remain missing

If an existing downstream contract requires a value, create the narrowest deterministic compatibility mapping possible without falsifying canonical truth.

7. MIRROR TEST FOUNDATION
Design the adapter so that these two wardrobes produce equivalent canonical styling semantics when their confirmed data is equivalent:

A. manually entered/correctly edited wardrobe
B. Gemini-classified wardrobe subsequently corrected by the user

AI provenance must not affect styling once canonical user-confirmed semantics are equivalent.

8. V3.7 PROTECTION
DO NOT modify:
- Recommendation Engine v3.7 scoring
- ranking
- candidate generation
- affinity/pair affinity
- weather logic
- outfit generation
- rotation logic
- benchmark definitions
- Track B
- Track C

The adapter must feed the existing machinery without changing its proven behaviour.

Do not "improve" recommendations as part of this task.

9. PHASE A PROTECTION
Do not modify:
- garment_groups schema
- garment_group_members schema
- Phase A migrations
- Phase A RLS/security
- existing group persistence lifecycle

Read and consume existing relationships only.

10. DATABASE
Prefer no migration.

Only add a migration if an existing canonical value genuinely cannot be represented or consumed without one.

Do not duplicate canonical wardrobe data into a second long-lived semantic table.

The adapter should be a deterministic projection/translation layer, not a second source of truth.

11. API/ARCHITECTURE
Use the existing architecture and persistence paths.

Do not create a new generic styling backend service unless the current architecture genuinely requires a small boundary module.

Prefer a small, well-named module/function with an explicit input/output contract.

Keep the contract strongly typed.

The output should be suitable for later use by:
- African context-aware styling
- Traditional styling
- Luxury Concierge
- existing v3.7 recommendation machinery

But DO NOT implement those features now.

12. TESTS
Add focused tests covering at minimum:

- canonical garment → styling semantics
- canonical African garment → preserved subtype/category semantics
- canonical colour/perceptual colour preservation
- explicit user correction → adapter uses corrected value
- explicit cleared value → remains unknown
- unknown values → no fabricated defaults
- group membership → relationship preserved
- coordinated_set → remains coordinated_set
- layered → remains layered
- equivalent manually-entered vs AI-then-corrected garment → equivalent semantic output
- deterministic repeatability
- no Gemini/provider invocation
- no mutation of canonical wardrobe data
- no changes to v3.7 behaviour

If an existing test harness already provides appropriate fixtures, reuse them.

13. VALIDATION
Run only targeted validation relevant to this change:

- focused P0.2 tests
- existing canonical semantic tests
- relevant group/relationship tests
- typecheck
- relevant lint
- relevant server/frontend tests
- git diff --check

If practical, run a targeted regression proving the frozen v3.7 output is unchanged for an existing fixture.

Do not run expensive whole-repository analysis unless required by an actual failure.

14. FILE/DIFF DISCIPLINE
Before editing, inspect only the specific files needed to establish:
- canonical WardrobeItem semantics
- P0.1 semantic persistence
- existing garment-group read contract
- current recommendation input boundary

Then implement the smallest coherent change.

Do not refactor unrelated code.

Do not rename existing public concepts merely for stylistic preference.

Do not rewrite existing working persistence.

STOP CONDITION
Stop after the canonical → Styling Intelligence boundary is implemented and validated.

Do NOT continue into:
- Traditional generation
- event/context modelling
- African-only mode
- African+Western intent
- Concierge
- Packing
- v3.7 changes
- recommendation tuning
- new taxonomy
- new AI providers

Final report must contain only:

1. Implemented
2. Semantic contract
3. Files changed
4. Tests/validation
5. Database changes (or "None")
6. Protected areas confirmed unchanged
7. Blockers

If the existing architecture already provides part of this boundary, reuse it rather than duplicating it.

Success criterion:
Amodka has one deterministic, strongly typed canonical wardrobe → Styling Intelligence boundary where user-confirmed wardrobe truth survives independently of AI provenance, African garment semantics are preserved, relationships remain explicit, unknown remains unknown, and the existing frozen recommendation engine can consume the projection without being modified.
