AMODKA — PROFILE SCREEN REDESIGN (quiet-luxury restructure)

GOAL
The Profile tab reads as a settings dump: about eight repeated "eyebrow + 
large bold black heading" blocks, Refinements groups (Physical, Style, 
Lifestyle) expanded by default with ~45 chips on the main scroll, and the 
Premium offer buried near the bottom. Redesign it as a calm, spacious 
hub: identity first, membership second, then quiet grouped rows. Heavy 
editing moves to pushed screens. Fix structure first, then surface 
styling.

DO NOT TOUCH
Recommendation Engine v3.7, Style Quiz logic, how Refinements are stored, 
loaded, saved and consumed (same data shape, keys, save timing), billing 
/ RevenueCat / entitlement logic (reuse the existing upgrade handler), 
auth, database schema/RLS, account-deletion behaviour, wear-log data, 
quota logic, and the AI-processing GATING logic (what may be sent and 
when). This is a presentation and navigation change, with one narrow 
exception for the AI row in item 8. Keep every existing testID and 
accessibility label (adding new ones is fine). No new dependencies, no 
new fonts. Use existing tokens from constants/colors.ts; list any token 
you add and why no existing one fit. Do not rewrite existing copy except 
the strings specified below.

STEP 0 — AUDIT (read-only; summarise in the report)
- Which files render the Profile tab and its sections.
- Every interactive element and its handler: avatar edit badge, the 
  pencil beside the name (same action?), Redo Style Quiz, every 
  Refinement control, weather toggle, unit switch, Wear Log, Personal 
  Intelligence chevron, the "Combination learning — Premium" lock row 
  (tappable? where does it lead?), AI Processing switch, Sign out, 
  Delete account, upgrade button.
- Where Refinements state lives and when it saves.
- How existing pushed screens are registered (follow that pattern).
- Fonts loaded and used.
- AI processing: how the choice is stored (is there a distinguishable 
  "no choice yet" state, or does it default to a boolean?), what the 
  gating checks, whether the disclosure is shown before EACH photo or 
  only before the first, what happens on decline, and the exact wording 
  of the disclosure sheet (report only; do not change it).
- Account deletion (exists; do NOT change behaviour). Report: the 
  confirmation shown; exactly what it deletes (auth user, wardrobe 
  rows, objects in the wardrobe-images bucket, profile and refinements 
  rows, bg_removal_usage, any bg_removal_cache entries tied to the 
  user, any other table keyed by user id); what it does NOT delete; 
  what happens to an active Premium subscription and whether the 
  confirmation says deleting the account does not cancel it. List 
  gaps as findings only; do not fix them in this task.

GLOBAL RULES
- Replace every "eyebrow + big H2" pair with ONE small label: 11pt, 
  uppercase, letterSpacing ~1.4, muted ink at >=4.5:1, set as an 
  accessibility header.
- Each group is one rounded card (radius 20), rows 56-64pt tall, title 
  16pt/500 ink, subtitle 13pt muted, trailing chevron (muted, 14pt) or 
  switch, hairline dividers inset 20pt. Screen padding 24; 32pt between 
  groups; 8pt grid.
- Remove all tinted icon tiles (sage, amber, pink, gold). Row icons are 
  20pt line icons in ink at ~70% opacity with no tile. The only gold 
  accent on the screen is the Membership star.

NEW STRUCTURE (top to bottom)

REFINEMENTS SCREEN (new pushed screen)
Header "Refinements" with back; keep the existing intro line 
("Optional — sharpen every recommendation across your wardrobe."). 
Physical / Style / Lifestyle are collapsible groups, each showing its 
progress ("3 / 3"). Only the first incomplete group is open on entry; 
opening one closes the others; contents lazy-mount. Chips: min height 
40 with hitSlop to 44, pill radius, 8pt gaps. Unselected: transparent 
with hairline border. Selected: ink fill, ivory text. Small uppercase 
label above each chip set; helper text (e.g. face shape) 13pt muted. 
"No sleeveless" / "No short skirts" as switch rows. Save behaviour 
exactly as today; do not add a Save button if it autosaves now. Moving 
the controls must not change what is stored.

PERSONAL INTELLIGENCE SCREEN (new pushed screen)
Use the existing strings verbatim: status line ("Learning… 0/5 signals 
before tuning kicks in"), explainer ("Loves, "not today" taps, and 
outfits you wear quietly shape what surfaces next. Nothing is ever 
fully banned."), then "Pieces you reach for" and "Pieces you skip" under 
11pt uppercase labels with their existing italic empty states, then the 
premium row as a regular row (small lock icon, chevron) leading where it 
leads today; if it is not tappable today, keep it non-tappable. Premium 
users keep today's unlocked behaviour.

MOTION AND INTERACTION
Press state: opacity ~0.72, no scale bounce. Transitions 180-240ms 
ease-out; accordion height via the existing reanimated setup. Respect 
Reduce Motion. Selection haptics on switches ONLY if expo-haptics is 
already installed.

ACCESSIBILITY
44pt minimum touch targets. Each switch's label includes its state. 
Screen-reader order matches visual order. Do not disable font scaling; 
layouts must hold at 130% font scale (rows grow, nothing clips or 
overlaps). Compute contrast for every text/background pair on the hub 
and both new screens. Text under 18pt needs 4.5:1. Known failures: 
white-on-gold button, tan initial on cream, amber Sign out text, pale 
chip text, error-red text. Include the table in the report.

TESTS
The suite runs Node tests, not React Native rendering, so extract logic 
into pure functions and test it: refinements progress (per group and 
total), hub subtitle strings, plan-pill state, empty-wardrobe invitation 
condition, Personal Intelligence subtitle, and the AI-row display state 
(unset / allowed / declined mapping to switch value and caption). Cases: 
empty, partial, complete. Counts must match what the current screen 
shows for the same data. Keep npm test, typecheck, lint and the golden 
set green.
