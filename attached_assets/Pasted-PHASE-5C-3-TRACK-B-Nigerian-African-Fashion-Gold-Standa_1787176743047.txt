PHASE 5C.3 — TRACK B
Nigerian/African Fashion Gold-Standard Dataset Construction & Independent Validation
Context

Track A — Nigeria/Africa Fashion Intelligence Capability Audit — is complete.

The audit concluded that Amodka's frozen Recommendation Engine v3.7 has a meaningful existing foundation for Nigerian/African fashion, but it is not yet defensible to claim Nigeria/Africa-ready recommendation or classification because we do not yet have independently authored Nigerian-fashion gold labels and a properly labelled image set.

The audit also identified several hypotheses requiring empirical validation:

missing cultural/occasion context;
scale-sensitive wax-print visual hierarchy;
coordinated Ankara/two-piece identity;
Nigerian climate/season modelling;
representation limitations for agbada, boubou, gele, aso-oke and related garments.

The benchmark protocol already defines 100 cases:

40 garment-understanding cases;
30 outfit-compatibility/competitive-set cases;
20 occasion cases;
10 weather/context cases.

1. Establish the benchmark governance model

Create a formal benchmark governance document.

It must define:

Gold-standard authority

The expected classification/ranking must come from an independent Nigerian/African fashion reviewer or stylist, not from the coding agent and not from the existing recommendation engine.

The reviewer should have demonstrable familiarity with Nigerian/African fashion.

The reviewer does not need access to source code.

Their job is to answer:

"What would a competent Nigerian/African fashion stylist consider the correct/strongest recommendation in this scenario?"

Independence requirement

The reviewer must assign gold labels before seeing Amodka's output.

The benchmark must therefore be structured as:

Scenario
      ↓
Candidate garments/outfits
      ↓
Independent stylist assigns gold labels
      ↓
Gold labels locked
      ↓
Amodka v3.7 runs
      ↓
Compare

Never:

Amodka result
      ↓
stylist adjusts answer

3. Define the gold-label schema

The benchmark must distinguish between different types of truth.

A — Garment classification

For each image:

garment category;
subtype;
pattern;
fabric;
pattern scale;
colour;
fit;
occasion/context;
confidence;
culturally relevant attributes;
reviewer rationale.

Do not force the reviewer to use an Amodka taxonomy value where that taxonomy cannot accurately represent the garment.

Instead record:

gold_label

and separately:

current_amodka_mapping

This is essential.

It allows us to discover whether the problem is:

"The reviewer knows what this is but Amodka cannot represent it."

rather than incorrectly calling it a classifier failure.

10. Explicit Ankara visual-weight tests

This is a priority.

Create paired cases such as:

Case B

Case C

Medium Ankara + solid ground.

Case D

Small Ankara + solid ground.

Case F

Two visually unrelated Ankara pieces.

The reviewer must explicitly score:

coordination;

This will tell us whether the existing pattern-safety system is genuinely suitable for African wax print.

11. Test coordinated-set identity

Create cases where:

Ankara top + matching Ankara bottom

competes against:

Ankara top + unrelated bottom

and:

solid top + solid bottom

The reviewer should explicitly state whether the matching set is:

superior;
equivalent;
inferior;

and why.

Do not assume that matching always wins.

The purpose is to test whether intentional coordination is being understood.

12. Create adversarial cases

At minimum:

Pattern overload

Multiple competing statement patterns.

Pattern suppression

Strong African print + excellent neutral grounding.

Cultural mismatch

Beautiful traditional garment in an inappropriate context.

Over-formalisation

Traditional garment unnecessarily outranking contemporary styling.

Western-default bias

Western outfit winning despite a culturally appropriate African outfit being clearly superior.

Material dominance

Expensive/luxurious material overwhelming contextual appropriateness.

Completeness dominance

Extra accessories causing an inferior outfit to win.

Weather mismatch

Heavy outfit beating a lighter weather-appropriate option.

13. Gold-label procedure

For every case:

Step 1

Prepare the scenario.

Step 2

Prepare candidate garments/outfits.

Step 3

Give the reviewer the scenario and candidates.

Step 4

Reviewer assigns:

acceptable/not acceptable;
ranking;
preferred outfit;
rationale.
Step 5

Lock the gold answer.

Step 6

Record reviewer sign-off.

Step 7

Only after the gold answer is locked may Amodka v3.7 be executed.

14. Reviewer scoring rubric

Create a simple, explicit rubric.

For outfit-ranking cases evaluate:

0–5

0–5

0–5

However:

Do not automatically convert these into the Amodka score.

They are reviewer evaluation dimensions.

The final gold ranking remains the reviewer's professional judgement.

15. Inter-rater reliability

If practical, recruit a second independent reviewer for a subset of cases.

Target at least:

20% of the benchmark

The second reviewer should independently score those cases before seeing the first reviewer's answers.

Calculate agreement where appropriate.

If reviewers disagree materially, flag the scenario rather than pretending there is an objective answer.

This is particularly important for fashion, where some cases have legitimate stylistic disagreement.

16. Image provenance and rights

For every image record capture:

source;
licence/permission status;
whether the image can legally be used for internal testing;
whether it can be committed to the repository;
whether it can be shared with the independent reviewer.

Do not download random internet images and place them into the repository without establishing usage rights.

If images cannot legally be stored in the repository, create a secure external/private dataset reference mechanism instead.

Do not put copyrighted third-party images into production.

17. Privacy

Do not use real users' personal wardrobe photographs for this benchmark unless explicit permission has been obtained for benchmark use.

Prefer:

licensed images;
purpose-created test images;
synthetic/generated images where appropriate;
explicitly consented images.

Do not upload benchmark images to third-party AI services simply to create the gold labels.

The gold-label process must remain independent.

expected winner.
