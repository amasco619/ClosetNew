## Approved Change 1 — P0

### Validate `dominantRgb` against `colorFamily`

Implement the server-side consistency validation identified in your audit.

Before making the change:

1. Inspect the existing `processGeminiResult()` implementation.
2. Confirm exactly how `dominantRgb`, `dominantHsl`, `dominantLab`, and `colorFamily` currently flow through the system.
3. Reuse existing colour utilities/constants wherever possible rather than creating duplicate colour logic.
4. Ensure the validation cannot introduce regressions for legitimate colours, especially colours near family boundaries.
5. Keep the threshold configurable rather than scattering a magic number through the code.
6. Preserve the existing Gemini response contract.

The desired behaviour is:

**Gemini classification → validate RGB/colourFamily consistency → normalise/correct if necessary → derive perceptual colour values → store wardrobe item**

Do not blindly overwrite valid Gemini data. The correction mechanism should be deterministic, explainable, and safe.

The objective is:

If the proposed architecture would require an additional Gemini classification call, STOP and report:

* latency implications

Graceful fallback is required:

## Approved Change 3 — P1

### Surface low-confidence classifications

Implement the low-confidence classification feedback mechanism.

The current proposal is:

**`modelConfidence < 0.65` → subtle "Review classification" indication**

Before implementing it:

1. Verify how `modelConfidence` is currently stored.
2. If it is not persisted with the wardrobe item, add the minimum required data support.
3. Avoid redesigning the wardrobe data model unnecessarily.
4. Make the `0.65` threshold easy to change later.
5. Do not prevent the user from using the garment merely because confidence is low.
6. Ensure the UI remains consistent with AuraCloset's existing premium/quiet-luxury design language.

The goal is to give users an opportunity to correct potentially incorrect classifications before those classifications negatively affect outfit recommendations.

**Gemini = garment classification**

**Algorithmic engine = outfit recommendation**

The existing algorithmic recommendation system should remain responsible for:

* candidate generation
* outfit compatibility
* scenario matching
* colour harmony
* formality
* pattern safety
* texture
* proportion
* weather
* body-type considerations
* wear history
* affinity/reaction signals
