Amodka — Bounded Personalization Consistency Fix

Implementation and verification report. Scope: the five fixes in the supplied specification. No publishing or deployment.

Executive result

All five targeted changes implemented. Final full suite: 106 passed, 0 failed test files.

Account hydration no longer falls back to another account's local profile. Guest migration includes face shape, preserves existing constraint/profile values, and cannot reuse an already-consumed guest snapshot for a later account. Skipping the primary goal completes coherently with Classic. Face shape now invalidates the rotation input hash. Controlled scorer tests document existing eye-colour and skin-tone effects without changing calculations.

The Track C result CSV has since been restored to the original 100-case snapshot; all 100 case IDs are unique and its validator now passes. Frozen and raw-output checksums pass.

Exact behavior and decisions

  1. Account-safe hydration: clear cached profile values while an authoritative read runs, then build from neutral defaults plus the current remote account. Remote null/missing answers do not inherit the previous account; false, zero and intentionally empty strings are not mistaken for absent values. Existing account/startup guards remain in place.
  2. Guest migration: only explicit guest-marked snapshots qualify for a blank account. Direct signed-in switches cannot nominate a guest snapshot. The shared existing-format serializer writes the top-level face shape into constraints._profile.faceShape, alongside the existing extended profile fields. Other constraint and extension keys are preserved. Successful hydration caches a non-guest snapshot, preventing later accidental re-migration. A failed guest migration write propagates failure, retains the guest cache, and does not claim success. Stale account completions cannot publish after their guarded async checkpoint.
  3. Primary-goal skip: completing the quiz without a selected goal saves classic. This matches the existing Classic blueprint fallback and keeps the startup required-field rule intact. Completed legacy profiles missing that goal normalize to Classic; an incomplete quiz is not automatically completed. Explicit goals remain unchanged.
  4. Rotation identity: face shape is added to computePoolHash. A changed face shape takes the existing hash-change reset path. Unchanged inputs remain stable; the shuffle and selector algorithms are untouched. The old serialized hash format will differ once after this update, so existing rotation state can reset once on first use.
  5. Scorer evidence/comments: tests change one profile dimension at a time against controlled metadata. A supported eye/colour match adds exactly +1; the tested non-match adds nothing. Supported skin-depth/contrast-colour combinations add exactly +1; non-matching tones or colours add nothing. The stale subtype comment now correctly states +3 for a primary subtype match, with no direct secondary subtype bonus. No weights or palettes changed.

Why this approach: remote account data is authoritative for account privacy; local guest migration is explicit rather than a fallback. Saving the existing Classic default is smaller and more coherent than relaxing completion routing. No new database column or migration was needed.
